2. **有一個真發現：規則嘅 close 界線同 FILLABLE 定義唔一樣。** 引擎收 `close >= S1`，而 spec 嘅 FILLABLE 要求 `close > S1`。美股 15 單、日股 59 單嘅收市價**啱啱好等於** S1，按 spec 定義唔算 FILLABLE。呢個唔係數據問題，係定義嘅邊界，要 Kenneth 決定。
3. **確認期成本：已量度，安慰劑顯示冇一個『代表性成本』可以攞出嚟。** 美股：中位跳空 0.0882% vs 安慰劑 0.0702%（差 +0.0180pp）；尾部 >3×ATR 0.195% vs 安慰劑 0.273%（差 -0.078pp）。日股：中位跳空 0.0% vs 安慰劑 0.0043%（差 -0.0043pp）；尾部 >3×ATR 0.656% vs 安慰劑 0.378%（差 +0.278pp）。中位跳空同安慰劑冇分別（安慰劑係由**同一隻股票嘅候選池**抽、只換「邊一日算訊號」呢個配對，樣本數、股票、價格環境、交易日曆全部不變）——即係話訊號日嘅隔夜跳空**冇系統性成本**。但**尾部唔一樣**：日股訊號日嘅 >3×ATR 佔比高過安慰劑。所以要上站嘅嘢係「等待成本嘅**分佈**」，唔係一個數字 —— 呢個正係 spec 要求「過濾率同成本分佈兩個一齊印」嘅原因。
4. **失效門檻：三條提案已寫好，等你批數字。** 冇批准之前唔上站。
5. **獨立 gate：做到，而且捉到嘢。** 植入舊 stamp 嘅負面控制令 gate 判 STALE（唔係 done）。live read-back 而家讀到真實頁面（stamp + 訊號數），唔係讀 build 自己嘅 manifest。

## 工作期間發現嘅問題（已修，但照講）

1. **重跑最初用錯咗引擎。** `data/bt10y_trades.json` 睇落似係啱嘅原料，但佢係 through-S1 breakout 變體（入場價高過 S1 5.8%），唔係 live v2。跟 spec 用 `data/bt10y2/` 凍結數據重跑，先對得上 `ab_close_hold.json`。
2. **`judge_row` 原本完全忽略 rule 參數** —— 雙向斷言嘅第一條（改 rule 個分類要變）根本無可能通過。係 fixture 逼我發現嘅。
3. **雙向斷言第二條嘅 zero-value row 撞咗 key**（同一個 sym\|date 覆蓋咗原 row），令 arm 讀到「原有分類變咗」。
4. **mutation arm 連續捉到我兩個砌得差嘅 fixture**：第一版把 `open` 寫死 100.0，於是股價高過 100 嘅名喺兩條 rule 下都判 inconsistent（冇得反轉）；第二版令一半 row 收市低過 S1，於是佢哋 baseline 已經 inconsistent。兩次都係 **fixture 錯、唔係 code 錯** —— 但如果 arm 唔會 fail，我根本唔會知道。第三版先砌到：每一行開市高過 S1、收市企穩 S1，flip side 先有嘢可反轉。
5. **excluded cohort 嘅「前瞻回報」原本用咗同日收市價**，根本唔係前瞻回報；已改成用同一套引擎規則（入場 S1、3×ATR 止損、10 日離場）計 hypothetical return。
6. **spec 嘅前提有錯**：spec 話 halt/suspension flags 已經喺 `data/`。實際上**全個 repo 冇任何 halt 旗標**（OHLC 只有 date/open/high/low/close/volume，`grep -rl halt data/` 零命中）。UNFILLABLE 只能用同一個 OHLC source 推導（零成交量／全日一個價），並且當作**推導值**而唔係供應商提供值。
